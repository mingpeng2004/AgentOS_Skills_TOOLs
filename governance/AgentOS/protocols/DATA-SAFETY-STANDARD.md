# AgentOS 数据维护安全协议 v1.0

> 用户 2026-10-23 裁决（**系统级硬要求**）：
> **「维护过程中的数据安全性是非常重要的一个项目，我们必须确保数据库的安全性，所以请系统级别的考虑这个事情，
> 并将安全对策导入到我们的治理体系中，平行展开，确保后续数据不会有这样的风险。」**
>
> 本协议把这句话变成**可机械执行、可阻断写入**的门禁。与 `DELIVERABLE-STANDARD.md` 并列执行（对应 R7）。
> 与 R6（数据库零臆测）互补：**R6 管"数据从哪来"，R7 管"数据怎么被安全改动"**。

---

## 0. 一句话定义

> **任何对既有数据的写入，必须先备份、可断言、可回滚、可验证。**

事故不是小概率事件，它是**并发 + 盲操作 + 无快照**三件事同时成立时的必然结果。

### 0.1 已发生的真实事故（作为反面基准，不得重演）

2026-10-23 金属材料库：164 行数据被清空，文档标题被改写为 `E9EFF2`。
根因三件套：

| 根因 | 表现 | 对策 |
|---|---|---|
| **共享文件** | 金属库与塑胶库同处一张表；清空类操作按**活动页签**生效 → 跨库误伤 | DS-2 库间隔离 |
| **无快照** | 清空前没有把目标区导出到本地 → 数据只能靠重建 | DS-3 写前快照 |
| **焦点未校验** | 向工具投递文本前没确认焦点元素 → 十六进制字符串落进**标题栏**并覆盖文件名 | DS-7 焦点校验 |

**判别口**：一个事故需要三个条件同时成立。**去掉任意一个，事故就不成立。**
本协议的三条硬约束（隔离、快照、断言）分别去掉一个条件。

## 1. 九条硬规则

| 编号 | 规则 | 等级 |
|---|---|---|
| **DS-1 单一事实源** | 每个数据库必须有**本地事实源文件**（TSV/CSV）+ SHA256 清单。表格是**投影**，不是唯一副本；表格被清空必须能 100% 重建 | 最高 |
| **DS-2 库间隔离** | 独立数据库必须分属**独立文件**。页签级隔离**不足**：清空、粘贴、重命名按**活动页签**生效，会跨库误伤 | 最高 |
| **DS-3 写前快照** | 任何写入前，目标区域必须整表导出到 `backups/`；**快照即回滚源**，缺快照不得写 | 最高 |
| **DS-4 目标断言** | 写入前必须断言「**文件标题 + 页签名 + 目标范围**」三者与预期一致；任一不符**立即中止**，不得"先写着再说" | 最高 |
| **DS-5 写后校验** | 写入后必须整表回读，与事实源**逐行逐格**比对；不一致 → **自动回滚**并如实报告失败，不得沉默 | 最高 |
| **DS-6 破坏性操作清单** | 清空、删列、删行、删页签、重命名文件、重命名页签、覆盖写 = 破坏性操作，须**显式确认** + 已有快照 | 最高 |
| **DS-7 焦点校验** | 向任何输入类操作投递文本前，必须校验**焦点元素身份**（名称框 / 标题框 / 网格 / 对话框），禁止盲投 | 最高 |
| **DS-8 纯文本化** | 数值型表格落表前，目标区先设为**纯文本**，杜绝 `08→8`、`12%→0.12`、日期串自动转换等**静默改型** | 最高 |
| **DS-9 审计留痕** | 每次写入留存：事实源哈希、快照路径+哈希、写前/写后行数、断言结果、校验结论、门禁报告 | 最高 |

## 2. 写入门禁 S0–S6（缺一即不得写）

| 步 | 动作 | 失败处理 |
|---|---|---|
| **S0** | 校验事实源：文件存在、哈希与清单一致、列数与行数符合预期 | 中止 |
| **S1** | 目标断言：文件标题含预期名、页签名匹配、目标范围与数据范围一致 | **中止**（不得写入） |
| **S2** | 写前快照：整表导出到 `backups/<时间戳>__<文件>__<页签>__before.tsv` | 中止 |
| **S3** | 纯文本化：目标区设为纯文本 | 记录并继续（但 D8 项算未达标） |
| **S4** | 写入 | — |
| **S5** | 写后校验：整表回读，与事实源逐行逐格比对 | 不一致 → 进入 S6 |
| **S6** | 自动回滚：把 S2 快照贴回原位；报告失败并保留证据 | 报告 **FAIL**，禁止交付 |

**参考实现**：`skills/professional-report-deliverable/scripts/` 旁的浏览器写入器
（本机实例：`_tools/safe_write.js`，S0–S6 全实现，返回结构化 JSON 报告）。
**前置检查脚本**：`skills/professional-report-deliverable/scripts/data_safety_preflight.py`。

## 3. 并发与隔离规则

1. **一个文件 = 一个库 + 一个写入者**。文件的所有权在协作开始时声明，别的会话不得写入。
2. **跨库合并的顺序不可反**：先各自成独立文件 → 各自校验通过 → 再由**单一写入者**合并 → 再校验。
3. 拆分时：先**复制**到新文件并校验 → 再从原文件**移除**。绝不能先删后建。
4. 发现"表里的数据不是我写的" → 立即停止写入，先做 S2 快照与全量比对，再决定动作。
5. 不在别的会话正在写的文件里做任何写操作（含改标题、改名、清空）。

---

## 4. 禁止行为

- ❌ 不快照就"清空整表再粘贴"
- ❌ 未断言页签名就粘贴
- ❌ 用 UI 盲改文档标题 / 文件名（DS-7 焦点陷阱的真实代价）
- ❌ 在没有本地事实源的情况下对表格做任何写操作
- ❌ 把"看起来合理"的数值写进主表（见 R6）
- ❌ 用"表格内容看着没问题"代替 S5 的逐行逐格比对
- ❌ 门禁红时改脚本/放宽关键词来"让它变绿"（沿用 `ZERO-GAP-STANDARD.md` §5.3）

## 5. 机械检查（可执行）

`data_safety_preflight.py` 校验**本地侧**不变量：

| 编号 | 检查 |
|---|---|
| P1 | 事实源文件存在、可读、UTF-8 无 BOM |
| P2 | 事实源 SHA256 与清单一致 |
| P3 | 事实源列数/行数符合预期 |
| P4 | `backups/` 存在且有快照（带时间戳） |
| P5 | 最近一次门禁报告 `status == PASS` |
| P6 | 表结构配置（目标文件标题 / 页签名 / 数据范围）与事实源一致 |

输出：PASS/FAIL + **可审阅清单**（逐条：文件、行、缺什么），不是二值判定。

## 6. 与既有协议的关系

| 协议 | 管的维度 | 与本协议关系 |
|---|---|---|
| `DELIVERABLE-STANDARD.md` R3 | 数据可推敲 | R7 是 R3 在**维护期**的落地 |
| `DELIVERABLE-STANDARD.md` R5 零缺口 | 交付不留白 | R7 保证"查不到/未核验"不会被手滑清掉 |
| `DELIVERABLE-STANDARD.md` R6 零臆测 | 数据从哪来 | R7 管数据怎么被安全改动，两者互补 |
| `DATABASE-INTEGRITY-STANDARD.md` | 逐格可溯源 | 本协议是其**写入侧**的安全护栏 |
| `TRUTH-AND-EVIDENCE.md` | 真值分级 | 本协议落地其"证据不得被销毁"的要求 |

**优先级**：最高，与 R1–R6 并列。
