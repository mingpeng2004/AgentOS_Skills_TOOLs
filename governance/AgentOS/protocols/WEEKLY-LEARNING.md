# Weekly cross-project learning and governed publication

Owner-authorized cadence: once weekly. Collect project lesson/decision/postmortem
changes, verify actual sources and integrate narrow reusable methods into the
corresponding authored Skill or governance rule. Use the registered local
Agent-rules-skills workflow and its validated scan/stage/prepare/publish tool.
The owner-designated public repository is mingpeng2004/AgentOS_Skills_TOOLs.

Skills are not promoted from anecdotes: require an applicable counterexample,
actual verification, source/version binding and a reviewed change. Reuse existing
project authority, client variants and skill catalog; no product behavior change
is implied by a maintenance task. No metrics, root cause or elapsed-time approval
may be invented. Unchanged sources need no artificial edit or empty commit.

Public output includes portable governance, reviewed Skill variants, original
notices/licenses, exhaustive discovery status and sanitized test/hash evidence.
Original private project paths, .agentos state, credentials, raw traces, dumps,
business source and measurements remain local. Vendor internal skills with no
established redistribution right remain reference-only in the catalog.

Native weekly scheduling is maintained by the calling client; installation of
this file adds no daemon. Verify saved schedule and actual publication readback.
Do not claim a future scheduled firing or unattended success before observing it.
Scan failures retain exact local reasons and appear as coverage gaps publicly.


## Unified assets and processed-learning boundary (2026-10-25)

Keep the existing capability registry authoritative; the portable distribution's capability-assets.json is a derived Skill/Tool index, not a second capability definition. Stable asset identity, version, capability references, runtime dependencies, side effects, rights, content hashes, canonical/conflicting/superseded state must be explicit. Reuse an existing method before proposing a new capability; a true blind spot begins as candidate, not an assertion of deployed competence.

Observation and adjudication watermarks are separate. A scan must not consume an unreviewed lesson. Use private source-bound receipts for strengthen/new/duplicate/blocked dispositions; require counterexample, normal and boundary evidence plus independent review before adoption. Unavailable client sources, inaccessible directories and scan limits remain visible, never equated to zero learning.

Repository readiness, managed baseline, pending writes and object caches are isolated by verified repository identity. Source tree additions/deletions, reparse/ancestor links and modified tests/review invalidate readiness. Check links with lstat/reparse identity, not following stat. Gate coverage and known-failure injection are part of the gate itself. Preserve existing source/history; binary/private/unknown-rights assets remain excluded or reference-only. Keep one native weekly automation; transfer its coordinating chat instead of duplicating it.

Portable deployment uses full preflight and verified backups/rollback. Personal signature/report-style defaults belong to an explicit optional owner profile. File parity, actual client activation, second-machine deployment and future scheduled firing are distinct acceptance claims.
