# AgentOS 推导纪律协议 v1.0

> **来源**：用户 2026-11-12 裁决 ——「我看到你的过往消息总是会有推论错误的问题，我现在需要你优化你的推导机制。
> 确保基于讯息的分析 100% 正确……我不希望再看到推论错了又纠正的问题；**如果讯息有缺口，那就想办法解决讯息缺口**。」
> **地位**：与 `TRUTH-AND-EVIDENCE.md`（证据真实性）、`ZERO-GAP-STANDARD.md`（交付物零缺口）并列执行。
> 前两者管"交付物长什么样"，**本协议管"结论是怎么来的"**。
> **适用**：所有在本机执行工程/取证/分析任务的 agent，不限项目。

---

## 0. 一句话定义

**结论强度 ≤ 证据强度；缺口先补证据，不许用推断填充。**

| | 允许 | 禁止 |
|---|---|---|
| 结论 | 「X = 5.05 g/档 `[实测]`（P0 扫描，2026-11-12，n=4）」 | 「X 大约 5g（未标来源）」 |
| 缺口 | 「丝印针号未取到；取证动作：万用表通断档量 4 路并填表（见指南 §6）」 | 「按常规应该就是 OUT1 接 PA5」 |
| 推断 | 「高阻态下 LED 未必导通 `[推论]`：依据 J42 每路 LED 阳极在 3V3 侧（原理图 p14）；**覆盖性检查：依据只覆盖"脚被拉低"态，不覆盖"脚高阻"态 ⇒ 结论改为"须实测"**」 | 把推断写成事实的口气 |

**判别口**：一个没读过原始资料的人，看完你的结论能否指出**它站在哪条证据上**？不能 ⇒ 降级或补证。

## 1. 证据等级标签（强制）

沿用宪法 §0 的词汇，中英并列：

| 标签 | 含义 | 必须附 |
|---|---|---|
| `[实测]` verified / observed | 仪器或真机读数 | 读数、量程/条件、时间 |
| `[图纸]` 原文可查 | 原理图页 / 手册表 / 数据手册条目 / 源码行 | **可定位出处**（页码/表号/文件:行） |
| `[推论]` derived | 由上面两者推出 | **依据链 + 覆盖性检查结论**（§2） |
| `[假设]` assumption | 尚无证据 | **如何取证 + 如何证伪 + 若错的影响面** |
| `[用户]` user-stated | 用户口述/裁决 | 原话要点（可引用） |
| `[规范]` normative | **规定应当怎么做**的规则/标准/定义（不是对世界的断言） | 出处（哪份规范、哪一条） |

> **文档级标记**：整篇都是规范/经验条目的文档（经验库、规则手册），在**文件头 40 行内**放
> `<!-- DERIVATION:NORMATIVE-DOC -->` ⇒ 门禁对它**跳过 S2/S4**（强度匹配），**仍做 S1/S3**。
> 标记必须显式、可审计；不得为了过门禁而滥用（技术结论多的文档不许标）。

**规则** [规范]
1. 同一段落内的技术结论**必须**带标签；无标签的句子不得承载技术判断。
2. `[推论]` **不得**使用 `[实测]`/`[图纸]` 的确定语气；反之亦然。
3. **强度不匹配即降级**：证据只支持"大概率"时，禁止写"就是/一定/保证"。
4. 标签**不可省略**，但可合并：`[图纸+实测]`、`[推论→实测]`（表示已被实测证伪或证实）。

## 2. 依据链与**覆盖性检查**（★最高频的推论错误源）

### 2.1 依据链格式

```
结论 ← 依据₁ ← 依据₂ ← …
```
每个依据都要能定位（`原理图 p14 J42 通道` / `手册 表1 第5行` / `实测 2026-11-12 117kΩ`）。

### 2.2 覆盖性检查（三问，缺一不可）

对**每条**依据问：

1. **状态覆盖**：该依据在本结论所处的**具体状态/工况**下还成立吗？
   （例：依据"LED 阳极在 3V3 侧 ⇒ 脚低则导通"**不覆盖**"脚高阻"态 ⇒ 结论不能跨态套用。）
2. **前提满足**：依据自己的前提在本题被满足吗？（供电、方向、时序、量程、版本）
3. **反例检验**：若前提不成立，结论会变成什么？⇒ 把它写出来，或降级为 `[假设]`。

### 2.3 禁止的推理捷径

| 捷径 | 为什么禁 | 正确做法 |
|---|---|---|
| **对称/类比代替查证**（"低电平会导通 ⇒ 高阻也会导通"） | 高阻无回流路径，结论反了 | 逐状态做电流路径分析（§2.2 Q1） |
| **用惯例补全**（"隔离通道的 VOUT/GND 应该接电源地"） | 惯例不是本板事实 | 查原理图该页；查不到 ⇒ 标 `[假设]` + 取证动作 |
| **用"通常做法"填缺口** | 缺口被掩盖，后续全部基于虚构 | 缺口→取证（§3） |
| **先给结论再找依据** | 结论会锚定后续解释 | 先列依据，结论最后写 |

## 3. 缺口即取证任务（**不许用推断填充**）

### 3.1 遇到缺口，当场三选一（**当场做，不是留到以后**）

| 动作 | 何时用 | 产出 |
|---|---|---|
| **C-取** | 证据在本机可得（渲染原图/找原始资料/写探针/查源码/量） | 立刻取；取不到再降级 |
| **C-问** | 证据只能由用户提供（实物读数/现场状态/主观裁决） | 一个**可执行**的问题 + **为什么需要** + **测什么/看什么/怎么判** |
| **C-标** | 暂时拿不到但必须先往下走 | 标 `[假设]` + 取证路径 + 若错的影响面 + 影响哪个决策 |

### 3.2 硬性禁止

- ❌ 用"常见做法/通常/应该是/大概是"**填补缺口**；
- ❌ 把缺口写成结论（"丝印 OUT1 对应 PA5"在没有实测时）；
- ❌ 把 `[假设]` 悄悄留在文档里而不标（**占位符也算缺口**，见 ZERO-GAP K1）；
- ❌ 因"结论看起来很合理"而跳过取证。

### 3.3 C-问 的质量标准

[规范] 问题必须让对方**能直接动手**：量哪两个点、看哪个波形、哪个值算通过。
反例：「你知道 J42 针序吗？」（不可执行）；正例：「H 桥断电，电阻档量 `SLEEP`↔`GND`，报读数（∞=无内置下拉 / <100k=有）」。

## 4. 输出前自洽扫描（★先自查再交付）

交付任何结论前跑三条扫描（工具或人工皆可）：

| 扫描 | 查什么 | 命中怎么办 |
|---|---|---|
| **S1 数值冲突** | 同一标识符/同一参数在同一批交付物里出现**不同值** | 必须裁决并说明适用条件，否则不交付 |
| **S2 结论-证据强度** | 强断言（必须/保证/就是/因此断定）是否站在弱证据上 | 降级措辞或补证 |
| **S3 未闭合缺口** | 缺口词（TBD/待实测/待确认/待补/**空格**）是否都带**取证路径** | 补取证路径或当场取 |

| **S4 弱化词与强断言并存** | 同一段既说"可能/大概/应该"又说"必须/保证/就是" | 统一措辞强度，或拆段并分别标注 |
> 机械实现：`bin/check_derivation_discipline.py`（S1/S2/S3/S4 扫描，退出码非 0 = 阻断；
> 支持 `--warn-only` 只报告；代码块按行占位跳过，**报告行号 = 文件真实行号**）。

## 5. 观测工具先校验（读数之前，先确认"我读的是不是那一面"）

取证前逐项确认：

| 检查 | 例子 |
|---|---|
| **方向/正反面** | 芯片丝印倒置 ⇒ 先判方向再读，别用"倒置"解释镜像 |
| **是不是原始资料** | 用低清手册图读芯片型号 ⇒ 只能当**线索**，结论标 `[假设]`，直到拿到高清原图/照片 |
| **单位/量程/极性** | 电阻档读 117kΩ 是**到 GND**；若丝印 GND 与 V− 不同源，结论要重算 |
| **被测对象是哪个** | 同一参数的**两个实例**（如主控 vs 驱动）不能混用 |
| **时间/版本** | 结论引用的资料版本 ≠ 当前实际版本 ⇒ 标 stale |

## 6. 可证伪性

每条技术结论附一行「**什么现象会推翻它**」。目的不是形式主义：
- 若你能立刻说出"什么会推翻它"，说明你知道自己依赖什么；
- 若说不出，说明这句是**信念**不是结论 ⇒ 降级为 `[假设]`。

## 7. 交付前自检清单（10 条，逐条勾）

- [ ] 每条技术结论都带证据等级标签
- [ ] 每个 `[推论]` 都写了依据链，且**覆盖性检查三问**都过了
- [ ] 每个 `[假设]` 都写了取证路径 + 证伪方法 + 影响面
- [ ] 全部缺口都已取/已问/已标，**没有**用推断填充
- [ ] 向用户提的问题都是**可执行**的（量哪里、看什么、什么算过）
- [ ] S1 数值冲突扫描通过
- [ ] S2 结论-证据强度扫描通过
- [ ] S3 未闭合缺口扫描通过
- [ ] 读图/读数类结论已过"观测工具校验"（方向/原始性/单位/对象/版本）
- [ ] 被推翻过的旧结论**已就地标注作废**，不是悄悄改掉（保留推翻痕迹）

## 8. 推翻痕迹（禁止静默改写）

发现自己先前的结论错了：

1. **保留原句**，紧跟一行 `~~作废（YYYY-MM-DD）：真因是…~~`；
2. 写清**真因**（错在哪个环节：状态未覆盖 / 惯例补全 / 工具未校验）；
3. 若该错误已进入交付物（文档/DEC/代码），**同步标注**；
4. 把这个错误**归入本协议的一条**，避免同型复发。

> 推论错了再纠正不是失败；**同型再犯**才是。本协议的存在就是为了把"同型再犯"变成可被门禁拦住的事件。

---

## 9. 下发与覆盖机制（保证"所有 Agent 都真的执行"）

协议写得再好，没有被加载就是零。本节规定**分发的落点、校验与验收**。

### 9.1 落点（按加载优先级）

| 层 | 文件 | 作用 |
|---|---|---|
| 宪法 | `constitution/AGENTOS-CONSTITUTION.md` §0 派生条款 | 推导纪律是 truth invariant 的组成部分，**不可按客户端或个人偏好豁免** |
| 加载序 | `runtime/AGENT-IMPORT.md` 第 5b 条 | **主分发点**：所有客户端都会读它 |
| 客户端适配器 | `adapters/{kimi,minimax,openclaw}/SKILL.md` | 各客户端入口的显式加载项 |
| 导入清单 | `runtime/IMPORT-MANIFEST.json` | 新协议与门禁登记为必需文件 |
| 项目层 | 各项目 `AGENTS.md` / `CLAUDE.md` | 项目自有纪律与本项目门禁入口 |

### 9.2 分发与验收工具

```
python bin/agentos_derivation_deploy.py --check   # 报告缺口，退出码 1 = 有缺口
python bin/agentos_derivation_deploy.py --fix     # 幂等补齐（写前备份）
```

- 目标集合来自 `runtime/client-adapters.json`（客户端 `rule_files` + AgentOS 治理 skill）
  与本机各项目 `AGENTS.md` / `CLAUDE.md`；**不往无关第三方 skill 里塞指针**。
- 指针块以 `<!-- AGENTOS:DERIVATION-DISCIPLINE:BEGIN/END -->` 包裹，**幂等、可整块删除回滚**。
- 每次执行产出回执 `runtime/derivation-deployment.json`（时间、覆盖数、缺口数、逐文件 SHA256）。
- **回执 = 覆盖证据**；"协议存在"不等于"已被加载"。

### 9.3 项目层落地要求

每个项目至少具备：
1. `AGENTS.md` 里的推导纪律指针（含协议路径与门禁命令）；
2. 一个**可复跑的门禁入口**（薄封装 AgentOS 实现，不复制逻辑）；
3. 一条登记该纪律的 **DEC**（谁在何时因何事引入）。

### 9.4 缺口台账（未闭合缺口必须留痕）

未闭合的缺口**不许只留在对话里**：登记成台账（编号 / 为什么阻塞 / 取证路径 / 判据 / 状态），
随交付物一起给用户。范例：`docs/v5m_analysis_reaudit_dec581.md` §4（8 项），
`docs/v5m_optionA_wiring_plan.md` §7（Q1~Q14）。
