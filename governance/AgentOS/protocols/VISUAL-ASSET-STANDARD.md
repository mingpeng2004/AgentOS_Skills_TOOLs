## 1. R4 配图是默认需求（不可跳过）

| # | 规则 | 等级 |
|---|---|---|
| R4 | 每份对外报告**必须**包含与内容匹配的图：示意图、流程图、数据图表、质感/实物图、动图 | 最高 |
| R5 | **能用图说明的必须用图**：需要看形状、看顺序、看变化速率、看空间关系的地方，用文字表格是失职 | 最高 |
| R6 | **需要动画说明的必须配动图**：过程、渐变、跳变、对比翻转 | 最高 |

### 1.1 「什么算需要图」的判据（照这个来，不要为了配图而配图）

只有文字表格**答不了**的问题才配图。判据：

| 场景 | 该配什么 | 例子 |
|---|---|---|
| 两个以上变量的**关系形状** | 散点图 / 曲线 | 密度与单价是不是线性关系 |
| **数量对比**与排序 | 条形图 | 八个材料族的加权总分差多少 |
| **同一对象的两个口径** | 并列条形 | 碳排的原生 vs 再生差 14 倍 |
| **过程有顺序** | 流程图 + 动图 | 阳极氧化五步：碱蚀→氧化→染色→封孔 |
| **量在连续变化** | 曲线 / 动图 | 良率从 95% 到 98%，良损怎么跳变 |
| **剖面在生长** | 分层剖面 + 动图 | 镀层逐层堆叠 |
| **空间关系 / 结构** | 示意图（**默认走 §6 实景概念渲染**） | 镀层结构、成型断面对比 |
| **场景 / 装置 / 方案** | 示意图（**默认走 §6 实景概念渲染**） | 一个点子大概长什么样 |
| **外观 / 质感差异** | 微距图 / 实物图 | 拉丝 vs 喷砂 vs PVD 哑黑 |
| **分类地图 / 矩阵** | 热力图 / 网格图 | 材料 × 品类覆盖度 |

**不该配图的**：纯数字罗列、定义性文字、只有 2–3 个数字的比较（表格更快）。

### 1.2 覆盖率底线

- 每份报告**至少 1 张图**；每 10 页正文**至少 1 张图或动图**。
- 超过 30 页的报告，图/动图页不少于 **8%** 的页数。
- 章节分隔页（divider）可以用一张质感图作视觉锚点，不计入上述比例。

## 2. 图必须承载信息，不能是装饰

### 2.1 每张图都要能回答一个具体问题

写图注时先回答这句话：**「这张图让读者看懂了什么？」** 答不出来就是装饰图，删掉。

### 2.2 图注是必填项，且必须写口径

图注不是装饰性说明（「下图展示了……」），必须包含：

1. **这张图是什么**（图号 + 主题）
2. **怎么读**（轴的含义 / 颜色含义 / 点的含义）
3. **数据口径**（来源、边界、样本量）
4. **缺口**（哪些数据没取到、为什么没上图）

示例（合格）：

> 图 2 · 各材料族碳排放因子，原生与再生两个口径并列（实心为原生，描边为再生）。
> 家族值取该族牌号的中位数（铜族含紫铜与黄铜两个自有因子，取中位更贴近多数牌号）。
> 数据取自牌号底稿的 cradle-to-gate 口径，钛族未取得。

### 2.3 数据缺口必须显式标注，不能静默丢弃

**这是本规范最重要的一条。** 图上少画了数据，读者必须能看出来是「没有数据」而不是「画漏了」。

- 图注里的**数量必须与图上实际画出的数量一致**。
- 未上图的数据要在图下列出（牌号名 / 条目名 + 缺失原因）。
- 绝不允许出现「图注写 37 个、图上只有 18 个点」这种情况。

> **判别口**：拿图注里的每个数字回去数图上的元素，对不上就是硬伤。

## 3. 图表的数据纪律

### 3.1 图表数字必须数据驱动，禁止手抄

- 图表**不允许**在绘图脚本里写死数字。脚本必须从**同一事实源**取数。
- 事实源就是报告表格用的那个源（底稿 JSON / 评分卡 / 内容源文件）。
- 底稿一改，表格和图**同时**变；不一致就是两份真相，必然漂移且漂移不报错。

### 3.2 图注里的数字也从同一源头来

图注要写「18 个牌号」这种数量时，这个数由脚本算出并落盘（如 `chart_stats.json`），
内容源**读取**它，而不是手写。

> 背景：独立盲审抓到过「图注写 37 个牌号、图上只有 18 个点」的硬伤。
> 根因是图上的点是**算**出来的、图注的数字是**手写**的。

### 3.3 口径敏感的字段要按语义解析，不能按位置

同一族的数据里，「原生/再生」这类双口径的**书写顺序不统一**是常态。
按位置取第一个数会把两族画反，而图看起来完全正常。

- 有标签的（`（再生）`/`（原生）`）→ 按标签语义识别。
- 无标签的 → 用**物理约束**（再生料的碳因子必定小于原生料；较小的即再生）。
- 两者冲突 → **告警**，不闷着。

### 3.4 坐标轴按数据分布收，不从 0 起

散点图的轴若从 0 开到最大值，80% 的点会挤在角落，图等于没画。
按实测范围收（留 5–10% 余量），让点铺开。

### 3.5 配色与主题一致

- 图表色板从**版式层的 theme 读**（同一份 token），不另抄一份 hex。
- 系列色按数据维度上色（材料族、类别），不用随机轮转。
- **系列数 > 调色板长度时必须扩色**，不能轮转复用 —— 轮转会导致两个类别同色，图例上分不出。

### 3.6 图表里的特殊字符

- 下标/上标（`₂`、`³`）在 Pillow 渲染时可能掉成豆腐块 → 图表内统一用 ASCII 写法（`CO2e`）。
- 中文标签必须用中文字体渲染，用拉丁字体渲染汉字会掉成方块。

## 4. 动图（GIF）规范

### 4.1 什么时候用动图

动图只在**必须有时间维度**的场景用：

1. **过程有顺序**（五步流程逐步展开）
2. **量在连续变化**（良率随批量爬升、成本随批量下降）
3. **剖面在生长**（镀层逐层堆叠）
4. **对比在翻转**（两方案排序随参数改变）

静态图能讲清的，**不要**用动图。动图是补充，不是标配。

### 4.2 首帧必须自解释

PPT 缩略图、PDF 导出、很多预览工具**只取首帧**。
所以 GIF 的**第一帧必须是完整可读的图**，不是动画的起点。

- 良率曲线图：首帧画完整曲线，之后再回退到起点重播。
- 流程图：首帧是完成态，之后回退重播全过程；末帧回到完成态，循环时不断裂。

### 4.3 帧间必须有可见差异

Pillow 会**合并像素完全相同的帧**。所以：

- 动画必须**连续插值**（膜厚平滑生长、曲线平滑展开），不能「每步一帧」的跳变。
- 合并后帧数要检查：`im.n_frames` 必须 > 1，否则等于静态图冒充动图。

### 4.4 PPTX 嵌入 GIF

- PPTX **支持** GIF 作为图片部件，放映时自动循环播放。
- 验证方式：解包后 `[Content_Types].xml` 里有 `Default Extension="gif" ContentType="image/gif"`，
  且 `ppt/media/` 下有 `.gif` 部件。
- **不要**用 `optimize=True` 存 GIF（会合并帧）。用 `optimize=False, disposal=2`。
- 动图页的脚注要写明「PDF 导出只保留首帧」。

## 5. 图片（质感 / 实物）规范

### 5.1 质感图要选对类别

微距实物图用于说明**表面形态差异**（拉丝/喷砂/阳极/PVD/滚压/蚀刻/抛光）。
prompt 要点：

- 「extreme macro」「industrial design material sample」
- 明确光位（soft studio lighting / raking light）与背景（neutral background）
- 明确「no text, no logo, no people」
- 产品级照片要「blank keycaps with no legends」「unbranded」——否则模型会生成乱码文字

### 5.2 质检：出图后必须人工看

生成模型的产出**不一定可用**。逐张看，剔除这些：

- 材质感不对（塑料感、颜色离谱）
- 构图像工具/杂物而不是材质样本
- 纹理形态与标注不符（如标「精铣」实际是拉丝）

不合格就重新生成（改 prompt），**不要**将就。已知的四张需重生案例见 §8。

### 5.3 网格排版的几何先算再排

方图（1:1）在 12.09" 宽的正文区里，12 张按 4×3 排会溢出（行高 3.56" × 3 行 = 10.67"）。

解法：**横向裁切条**（coverRatio ≈ 1.7:1），行高降到 1.6" 以内。
方图保持原比例居中裁切，**不拉伸**（拉伸会把纹理拉成横条，像印刷网点而不像金属）。

排版前用脚本把 `cols × rows × (图高 + 文字高)` 算一遍，别靠试错——试错一轮就是一轮编译+渲染。

### 5.4 版式层必须兜住溢出

网格总高超出可用高度时，**版式要抛错**，不能压扁、不能默默溢出到页脚。
这类几何问题必须由版式层兜住，不能靠人记得算。

## 6. 示意图的默认水准：实景概念渲染（两层法）

> **用户裁决（2026-10-23）**：报告配图若达不到本节的**实景概念渲染**水准，视为未完成。
> 本节是**默认输出水准**，不是可选项；用户不再单独提出该要求。
> 可执行实现：`skills/visual-asset-production/`（AgentOS bundled skill，能力 ID `vis-concept-illustration`）。

### 6.1 两条铁律

1. **示意图 = 生成式实景概念渲染（底图） + 程序化矢量标注层（信息层）**
   - 底图负责**形象逼真**；信息层负责**可审校**。
   - **底图禁字**：生成图里不得出现任何文字、数字、字母、水印、标签。
     文字与数值一律由程序叠加 —— 只有程序画出来的字才可审校、才不臆造、才不会被模型数错。
2. **文字筛查是硬闸门**：出图后必须过筛查并**逐张目检**。
   模型会在展板、表格纸、书本、便签、记录单上自己写英文（乱码/伪手写），**一律重做**。

### 6.2 为什么不允许用「纯线条示意图」交差

线条示意图能表达结构与流程，但表达不了**质感、尺度、真实场景**。
用户对本次湘乡 50 届交付的配图评价是「非常棒」，并要求把这套水准固化为默认 ——
**达不到就是降级，不是风格偏好**。

### 6.3 三条硬点

| # | 规则 | 等级 |
|---|---|---|
| R8 | 示意图默认走 §6 两层法；底图零文字、零人脸，信息层全部由程序叠加并来自事实源 | 最高 |
| R9 | 底图出图后必须过**文字筛查 + 逐张目检**；命中模型的乱码文字一律重做 | 最高 |
| R10 | 成品图压缩为 JPEG q94/4:4:4；**改编码前必须做像素级差分验证**（全图最大差 ≤24/255） | 高 |

### 6.4 与既有章节的关系

- §3（图表数据纪律）**不变**：要精确表达数据关系的图用真正的数据图表，**不要**用生成图。
- §5（质感/实物图）**不变**：实物表面形态差异仍用微距图。
- §7（资产体积与门禁）**收紧**：成品图默认走 JPEG，PNG 不存连续调图像。
- §8（交付前检查）**追加**：示意图必须过文字筛查与真机渲染扫查。

## 7. 资产体积与门禁

### 7.1 压缩是硬要求

AI 生成的 2K 图单张 3–8 MB，直接进 PPTX 会把 4 MB 的报告撑到 60 MB+。

- 质感照片：最长边 1200 px，JPEG q=88
- **实景概念渲染成品图：最长边 1700 px，JPEG q=94 / 4:4:4**
  （PNG 存连续调图像会到 1.9 MB/张，JPEG 只要 0.37 MB —— 差 7 倍；
  40 图的报告用 PNG 会让 PPTX 涨到 110 MB+。**改编码前必须做像素级差分验证**。）
- 图表 PNG：最长边 1700 px，P 模式 256 色量化
- 动图 GIF：最长边 1000 px，128 色调色板

目标：资产总量压到原始的 10% 以内，PPTX 体积可控。

### 7.2 必须有资产完整性门禁

配图引入后，「内容里写了图、产物里没有图」成为新的静默丢失风险
（页数对、其它门禁全绿，只是那页的图是空的）。

门禁要查：

1. 内容源声明的每个资产引用，**编译时实际用到的那一份**必须存在
2. PPTX 的 media 部件里必须真的有这些图（按尺寸/字节比对，不是按文件名）
3. 声明数 = 实际用数
4. GIF 帧数 > 1
5. `[Content_Types].xml` 含 `image/gif`

### 7.3 门禁必须做负控制

门禁自己**去 assets 里找一个同名文件**当通过，是无效的：
把文件改名，它会自动回落到另一份同源文件，然后报「通过」——门禁在自我安慰。

正确做法：核对**编译时写出的资产清单**（`used_<lang>.json`），
那是编译那一刻真正被嵌进去的那一份。

**每道新门禁都要做一次负控制**（改坏一个输入，确认它会报错），否则不知道它是否在工作。

## 8. 交付前必须做的检查

### 8.1 独立盲审

机器门禁查不出**语义自洽**问题（图注与正文矛盾、数量与图上不符、图被裁坏）。
交付前用独立子代理盲审：给它一份它没参与生产的交付物 + 原始事实源 + 明确验收清单，
要求逐条给「已修/未修/无法核实 + 证据」。

盲审最常抓到的（本轮实例）：

- 图注写「37 个牌号」而图上只有 18 个点
- 缺口列表只列了 8 个（实际 19 个），且尾部被画布右缘截断
- 碳因子图原生/再生两值颠倒（数值顺序不固定，按位置取就会反）
- 图表底部说明与轴标题重叠成一团

### 8.2 全页扫查

逐页打开 90 页既慢又容易漏。把实渲染图拼成 contact sheet（5×4 一张），
一眼看出空白页、溢出页、裁切错误的页。

### 8.3 双语检查

图表与动图**按语言各出一份**（`name_<lang>.png`），图内文字也要跟着换。
英文版里出现中文标签 = 交付事故。

## 9. 图片样式与幻灯片骨架（2026-10-24 用户裁决 · 全局生效）

本节对**所有**报告类交付的图片生效（不只是幻灯片）。用户两次否决 AI 模板感后定稿。

### 9.1 图片样式（硬要求）

| 项 | 要求 |
|---|---|
| 圆角 | **R2**（约 2px，1600px 画布口径），插图/照片/图标/示意图成品一律 |
| 描边 | **去除**，不要细边框线 |
| 投影 | **2 mm** 软投影（约 16% 不透明度，方向 90°） |
| 窄色条 | 强调短线与区块竖条：**两端圆弧收尾（胶囊形）** + 同样的投影 |

**判别口**：看图时如果边缘是直角且压在白底上像贴纸，就是漏了圆角与投影。

### 9.2 幻灯片骨架 = 手册化

配色用砂铜（底 `#FFFFFF` / 主 `#A8895F` / 辅 `#6E8B74` / 线 `#E8E4DD`），
但**去掉每页复制的模板骨架**：kicker 小节标、标题下横线、页脚上方横线、圆角卡片底色、
表格色块与斑马纹。正文落在白底，强调色只作短细线。
封面用**满版照片 + 左半不透明纯白硬边块**（不要渐变遮罩）。

**为什么**：AI 味来自骨架的重复，不是颜色。换配色不解决，必须拆骨架。

### 9.3 排版不许重叠、语言不许串 —— 四道构建期门禁

1. **文字碰撞检测**：按真实字体度量算占位，与其它文本/照片相交即构建失败。
2. **几何门禁**：形状越出画布或压进页脚带即构建失败。
3. **图号自动排序**：按出现顺序在构建末尾重排，禁止手写。
4. **英文版中文泄漏检测**：英文 deck 出现任何汉字（署名标语除外）即构建失败。

第 4 道为什么必须在**构建期**：英文版的取值链几乎总是终止在一张用源语言写的源表上，
字段没有英文半边时常规做法是「回退到源值」，而**回退是静默的**。事后门禁只能报告
不能阻止。**判别口**：取值函数里只要有 `en or zh` 这种回退，就必须配一道构建期泄漏检测。

英文版另加一道：不得残留中文排版标点（～（）：；、，　与全角引号与书名号《》），
在写文本的唯一收口处归一。

**判别口**：用户说「有字体重叠」而你只靠眼睛看 —— 这就是没做碰撞检测。
实现见 skill `professional-report-deliverable` 的 `scripts/deckkit.py` 与 `scripts/deck_gate.py`。

### 9.4 交付物自检必须跑在交付文件上

规格文件通过 ≠ 交付文件通过。**PDF 可能是旧构建产物**：PPTX 改了、PDF 没重导，
于是同一批交付里两份文件内容互相矛盾，而门禁对陈旧文件判绿。

**收尾时必须核对**：每份 PDF 的时间戳晚于其对应的 PPTX，且两者的文本层一致。

### 9.5 图里的文字也要查碰撞

PPT 层的碰撞门禁**看不见烘进图片的文字**（示意图、图表、流程图）。
要在图片层再做一次：量每个文字对象的真实包围盒，与其它文字、尺寸线、箭头求交。

**检测器要排除「引出线碰到它自己的标签」这种自碰**，否则误报会淹没真问题。

### 9.6 图文相符：声称有的东西必须真的有

页面写着「右图为该标准原文页面」「动图 34 帧」，实际那页 0 张图、整份 deck 0 个 GIF，
这是**交付物在说它没有的东西**，比排版难看严重得多。

**凡是声称「有图 / 有动图 / 有表格 / 有页码」的文案，必须由构建期的事实驱动**：
对象在就写"有"，不在就改文案，不要写死。顺手查取值链——**列名写错一个字符，
图片就会永远取不到**，而这类 bug 不报错，只让图消失。

### 9.7 照片池纪律：一张图只讲一件事（2026-10-24 用户实测退回 · 全局生效）

用户在「金属制程数据库」一轮里退回过一次：「图片有缺失情况，还有不能完整表达意思的情况」。
**图片缺失**与**图片不达意**是两个独立故障，必须分开修。

1. **按角色建池，不按主题建池**：一个主题要出 16 张（封面 1 + 工序链 6 + 设备 3 +
   检测 3 + 应用 3），**同一张照片只能用一次**。否则读者在第 3 页和第 6 页
   看到同一张图却以为在讲两件事。
2. **取图用分类、不用搜索**：关键词搜索会把题材完全错误的图排在前面。
   优先「Foundries / Die casting machines / Rolling mills」这类设备与工序分类，
   再补「Aluminium castings / Forgings」这类产品分类。
3. **筛选在截断之前**：先取前 N 张再筛，好图一张都轮不上。
4. **制程强相关词硬闸**：标题或描述必须出现该主题的专属工艺词；
   分类可信时豁免，不可信时必须过闸。同时剔除非照片（图纸/流程图/渲染图）
   与题不对意的对象（首饰、街道、法律文书、纪念碑、超市货架）。
5. **每个角色有门槛分**：达不到门槛的不许进这个角色；宁可标注
   「本主题暂无独立照片，此为通用场景」，也不放一张不对题的图。
6. **每张照片写「这张拍的是什么」**：用中文写，不是把英文文件名列出来；
   描述不出来就如实说描述不出来，不许编。
7. **流程链每个节点配自己那张图**：节点 1 和节点 4 出现同一张照片，
   读者就会说"这张图没把意思表达清楚"。

**判别口**：逐页数一遍——同一张照片在一份稿里出现几次；每张图能不能用一句话
说清它为什么在这一页。有一个答不上来就是没做完。

### 9.8 工程图示：实景底图 + 标注层（2026-10-25 金属制程库 DFM 章节实测 · 全局生效）

> 用户裁决（2026-10-25）：「DFM 设计准则页」这类**以零件本身讲规则**的图，
> 线条素画不合格，必须升级为**实景质感底图 + 图形化标注 + 编号铁律 + ✅/❌ 对比**。

**六条硬点**（每条都是本轮踩出来的）：

1. **缩放必须按像素，不按画布单位**。
   画布坐标（4.1 in = 100 单位）和位图分辨率（3168×1344）是两套单位。
   把画布单位当像素数用，等于把 3168 px 的图压进 48×25 px 再由渲染器放大 ——
   **出来的图一律发灰、发糊**，而所有其他门禁照样全绿。
   正确做法：先按 `dpi × 画布宽 ÷ 坐标跨度` 把框换算成像素，再**一次**降采样。
   **判别口**：量一下成图的实际像素尺寸，与画布尺寸对不上就是错的。

2. **锚点要实测，不要照抄模型写的**。
   模型写提示词时看不到图，给出的锚点必然是名义中心（实测 481 个锚点里 336 个是 0.5/0.5）。
   指一条到空纸上的引出线等于没有引出线。做法：**取零件的质心，再吸附到最近的
   有结构（局部对比度）处**，并限制吸附半径。

3. **底图只许扩，不许切**。
   画幅比例与零件比例不一致时，裁切窗口要**扩**到装得下零件为止；
   实在装不下才退回「等比内接 + 留白」。**零件被裁掉一半 = 图没说明任何事**。

4. **图上不许印未核实的数值**。
   参照海报上有公式行，但公式若是「车间比例」而非本项目事实源核到的值，
   印上去就变成未核实数值进了交付物。**数值只留在要点列表里，图内只留描述性标签**。

5. **标签牌宽度用渲染器实测，不靠估算**。
   英文标签约为中文的三倍宽，按字符数估算容易偏，估短了字就跑到牌子外面。
   用 `get_window_extent` 量，并把「缩到最小仍装不下」设为一条门禁。

6. **版面收紧时先缩字，不缩图**。
   图被放进更矮的框里会按高适配而**变窄**，三栏排下来中间就长出白缝 —— 看着像做错了。
   字号小一号只是密一点。所以：**图保持满栏宽与原生比例，字号有下限，
   两者都到下限才允许裁段落**。

**判别口**：把图放到幻灯片上量实际宽度。**不满栏**就是图被缩过了；
**像素尺寸对不上画布**就是缩放写错了。

### 9.9 图示判定层与徽章（2026-10-25 金属制程库 DFM 章节盲审整改 · 全局生效）

> 盲审在 DFM 章节抓到：240 张线图里 48 张**没有任何绿/红判定标**，
> 有「好特征被画成缺陷红」，而且线图章节的「好的一边在右」，与照片章节**相反**。
> 读者因此无法判断哪边是对的做法。

**五条硬点**：

1. **判定必须是声明式数据，不是逐图手写**。
   「哪一边是推荐做法、哪一边是错误做法」是**内容**，要能单独审阅、能单独改。
   做法：单独一份判定文件（按图注或条目键定位），**加载期**套用到图配方上，
   渲染器、门禁、构建器读同一份真相。**手写在配方里的标记必然漏**。

2. **徽章要白底 + 同色描边 + 绘制式 √/×，半径固定**。
   半透明小圆点直接压在图形上，在剖面线图上像**污渍**，在缩略图上根本认不出。
   徽章半径用**画布单位常量**，不随面板大小变 —— 读者不该每页重新适应一次徽章多大。
   字符（√/×）取决于字体有没有那个字，**一律画出来，不印字符**。

3. **徽章要自动找空位，先量墨迹再放**。
   不透明徽章落在哪里就盖住哪里。做法：按图元坐标估算面板的墨迹范围
   （含**标签文字**的实测宽度），按固定顺序试角落（图注带 → 内侧四角），
   取第一个不压内容的。**徽章盖住标签 = 藏掉了它要解释的那个词**。

4. **好坏左右顺序全局统一**。
   同一套交付物里，照片章节与线图章节必须同侧（图示章节统一 ✓左/✗右）。
   顺序写反读者要每页重新学一遍。判定层在加载期自动对调「坏-好」对。

5. **缺陷红只许画在缺陷上**。
   红色在这套视觉语言里只有一个意思：「这里是错的」。**好特征不得用缺陷红**，
   否则读者读到的是相反的信号。逐面板的改色表与判定表同源、同审。

**判别口**：随机抽一页，只看徽章 —— **说不清哪边是对的做法**，就是没做完。

### 9.10 双语同源切分（2026-10-25 金属制程库中英对等整改 · 全局生效）

> 盲审抓到：同一字段在中文版与英文版被切在不同位置，**英文版丢失了中文版仍有的
> 量化内容**（同一页上，英文读者看不到中文读者能看到的数值）。

**五条硬点**：

1. **截断按高度切，两语必然切在不同位置**。
   英文正文约为中文的 3.5–4.1 倍字符数，断句位置也不同；按框高切，
   英文一定先切完，尾部量化值只留在中文页。**这不是翻译问题，是切分问题**。

2. **切点要按两语共有的数字对齐**。
   同一字段的两半是同一内容的翻译，**数字序列是它们唯一共同的锚点**。
   做法：取两串数字的**最长公共子序列**，以「最后一个在两版都放得下的数字」
   决定切点；英文允许缩小一号字以容纳同样内容。**两版因此承载同一批事实**。

3. **英文半边不要预设为整句**。
   不少字段的英文半边**就是同一张条款清单的翻译**，只是用半角括号。
   判定依据不是「是不是中文」，而是**结构**：多数条目以括号条款号收尾 → 同样拆分；
   否则（整句说明）保持整段。**一律不拆英文 = 英文页整段丢掉条款号**。

4. **条目不要用固定字符数截**。
   英文正文约为中文的 3–4 倍，固定 150 字符的截断**必然切在量化内容中间**，
   英文版因此少几个数。做法：**条目本身不截**，让版面去容纳它（主栏加宽、英文版允许小一号字）；
   截断只允许发生在**两语共有的数字边界**上。

5. **数字集合比对要作为门禁**。
   逐页比对中英两版的数字集合；**中文多出的每一个数字都是英文版的缺口**。
   配一个**负控制**（人为删掉英文侧的数字，门禁必须报出来）。

**判别口**：把两版同一页的数字集合做差 —— **差集非空就是没做完**。

### 9.11 括号里的东西：引用还是旁注（2026-10-25 金属制程库中英对等整改 · 全局生效）

> 盲审抓到：条款清单里**每个括号都被当成条款号**，
> 于是「（该标准不规定冷轧压下率）」「（最大扭矩）」「（含M6）」这些**旁注**
> 被搬进了引用位，方法名与限定条件从正文里消失，散文被当成条款号显示。

**四条硬点**：

1. **括号先分类，再决定放哪**。引用位只放「指向标准某处」的组（条款号、表号、附录号）；
   其余（解释、方法名、限定条件）**留在正文里**。判据：有数字或以表/图/附录/第开头，
   且不含「未明示/未规定/不规定/does not specify」这类散文词、不含冒号。
2. **只把「引用」那一组从正文里摘出去**，其余括号原样保留。
   把所有括号都剥掉 = 静默丢内容。
3. **两语条目按引用配对，不按位置**。中文一条里塞了两件事、英文用分号切成两条时，
   按位置配对会让后面每一条的条款号**整体错位**。按引用对齐：中文一条取英文到
   **同一条引用为止**的那几条合并；合并时**前面的引用要回到正文里**，否则英文版会少一个数。
4. **引用在英文页用半角括号**。全角括号是中文排版，英文页出现全角括号 = 排版泄漏。

**判别口**：随机挑一条，看引用位里的是不是「一个可以去查的位置」——
不是位置而是句子，就是旁注放错了地方。
