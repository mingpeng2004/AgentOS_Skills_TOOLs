## 2. R2 中英双语交付

### 2.1 交付结构

每份对外报告交付**两套完整文件**，缺一不可：

```
<交付目录>/
├─ <报告名>            （中文版，.md + .html + .pdf）
├─ <报告名>-EN / <English Title>   （英文版，.md + .html + .pdf）
└─ build_report.py 等生成器（若有）
```

- 每套都要齐 `.md`（可编辑源）、`.html`（排版母版）、`.pdf`（分发终稿）三件套。
- **只给一种语言 = 未交付**。不得以"时间不够""英文版可后补"为由只交中文。
- 目录用 `中文版/` 与 `English/` 两个子目录或显式语言后缀，二选一但**全项目一致**。

### 2.2 两版对等性

英文版不是摘要、不是节译、不是机翻直出。它是**同等的专业交付物**：

- 章节结构**一一对应**，编号体系一致
- 表格**行数与列数完全一致**，每行对应同一行事实
- 所有数字、标准号、单位、参数、量程、版本号、日期**逐字一致**
- 结论条数一致，不多不少，不合并、不省略
- 英文版**不得新增**中文版没有的数据、结论或建议
- 英文版**不得弱化**中文版的限定条件（"通常""约""指示性""待核实"等必须保留）

### 2.3 术语与表达

- 关键术语**首次出现给中英对照**，如"硬质阳极氧化（hard anodizing）"。
- 标准号、AMS/MIL/ISO 编号、单位符号、牌号（6061-T6、a-C:H、ta-C）**保持原样，不翻译**。
- 中文版与英文版的图表标题、表头、图注也要对应，不得一边详一边略。
- 英文用专业领域惯用表达，不用机翻腔；`anodizing` 不是 `oxidation`，
  `coating` 不是 `plating`（电镀才用 plating），`hard anodize` 不用 `hard oxide`。

### 2.4 双语的自检

交付前必须核对：

1. 两版章节标题数一致
2. 两版表格数量、总行数一致
3. 两版数字集合一致（可用脚本抽取全部数字与标准号做集合比对）
4. 两版署名都是 `${OWNER_SIGNATURE}`

## 3. R3 数据 100% 可推敲

用户的原话：**"数据是经得起推敲的，代表顶级专家的专业水准。"**

### 3.1 每条数据必须可追溯

报告中的每个数字、标准号、参数区间、材料牌号都必须能回答"从哪来的"：

| 数据类别 | 必须标注 | 禁止 |
|---|---|---|
| 标准里写明的 | 标准号 + 版次 + 条款位置 | 只写数值不写出处 |
| 期刊文献的 | 作者/期刊/年份或 DOI | 把单篇论文结论当通用定律 |
| 供应商资料的 | 供应商 + "指示性参考值"字样 | 当成工程依据、被引用到结论里 |
| 推导出来的 | 推导方法 + 前提 | 只给结果不给路径 |
| 未能核实的 | 标 `unknown`/`待核实` + 写明怎么核 | 用确定语气陈述 |

### 3.2 标准号的三条纪律

1. **版次必须回官方平台核对**（ISO 官方目录、ASSIST、国家标准信息公共服务平台等）。
   已实测的坑：ISO 8077:1984 早已废止却仍被引用；ISO 8081:2021 是**化学转化涂层**标准，
   却被大量资料误称为"阳极氧化国际标准"。
2. **不同规范里同名 Type 含义不同**（如 MIL-DTL-53039E 与 MIL-PRF-24712 都发生过类型编号重排），
   引用必须带文件号与版次。
3. **未能核实现行版次的标准**，必须显式写"本次未核到现行版次，引用前须回官方平台核对"，
   并且**不得用这类标准去支撑正文中的任何参数或结论**。

### 3.3 冲突与不确定的处理

- 两个可靠来源冲突 → 显式写明冲突，给出各自口径与适用条件，**不悄悄选一个**。
  典型例子："DLC 盐雾 1000 h" 与 "DLC 不提供腐蚀保护"并不矛盾——前者是完整多层体系，后者是单层。
- 供应商的对比表数据（寿命倍数、检测时长、单价）即使标注了测试方法，若未说明
  膜厚/前处理/基材/划线状态，**数据不可比**，必须标注。
- 目录上标称的性能值（摩擦系数、寿命倍数）**必须追问测试条件**；没有条件的数值没有决策价值。

### 3.4 交付前独立盲审（不可省）

**自检不等于合格。** 机器可检测的缺陷（几何溢出、越界、占位符、算术加总、页数）自检能覆盖；
**语义自洽与事实自洽自检覆盖不了**。

交付前必须用**未参与生产**的独立子智能体做盲审，给它：

- 交付物本身
- 原始事实源（标准目录、原始数据表、文献）
- 明确的验收清单

要求它逐条给「已修 / 未修 / 无法核实 + 证据」。它最有价值的产出往往不是"你做错了什么"，
而是**它读出了你自己看不见的内在矛盾**（同一件事在两页里说法不同）。

盲审发现的阻塞项必须修完再交付，并在交付说明里如实交代。

### 3.5 禁止的行为

- 把模型记忆里的"大概是这个数量级"当事实写
- 用"约 100 小时"这种话掩盖没查
- 把单个供应商的宣传数字放进结论
- 自行推算标准号、版次或型号
- 用"业界普遍认为"代替来源

### 3.6 数据自洽的机械校验（盲审实证的高产区）

以下六类缺陷**自检脚本全都查不出来**，因为每个数字单独看都"像对的"。交付前必须人工过一遍。

| # | 缺陷 | 机械校验动作 | 判别口 |
|---|---|---|---|
| 1 | **结论倍数与自身基础数据矛盾** | 结论句里出现"几倍 / 多几成 / 高百分之几"时，**拿它除一遍本章的基础数据表** | 算一遍，而不是读一遍 |
| 2 | **单位换算凭印象** | 任何跨单位换算（HV↔HRC、HV↔GPa、psi↔MPa、℃↔℉）**查表反查** | 换算表非线性，记忆里的"大概值"普遍偏高 |
| 3 | **引用清单是冻结的** | 母标准的规范性引用清单锁在旧版次，**逐条核现行版次**，表格分两列：`引用版次` / `现行版次` | 照抄母标准的引用清单 = 交付一堆过期版次 |
| 4 | **标"未核证"却断言了标题** | 核证栏写"未核到"时，行标签里**不得出现任何标题或范围描述** | 没核到就不能给内容 |
| 5 | **数据分档未一致执行** | 报告自订了"标准/文献可直接引用、供应商数据须标指示性"这类分档规则后，**逐条回查正文是否都标了** | 规则存在 ≠ 规则被执行 |
| 6 | **两版结论强度漂移** | 限定词（"通常/约/往往/指示性/待核实"）与方向性动词（"提高/降低""优于/劣于"）逐条对读 | 英文版最易把"通常下降 20–50%"写成"decreases 20–50%" |

**辅助：两版数值集合比对脚本**（可复用）
抽取两版全部"数字+单位" token 做集合比较，要求**一版的数值集合必须是另一版的子集**，
再对出现次数不等的量打印上下文逐个确认是列表编号、句末标点还是真实数据差异。

## 4. R5 零缺口

用户的原话：**「以后所有的报告不能有缺口」**（2026-10-23 裁决）。

**零缺口 ≠ 零不确定。** 零缺口 = 报告里**每一处**都落到一个**明确结论**；不允许留下
「未公开 / 待确认 / 留空 / —」这类悬空项，让读者自己填空。

### 4.1 五类缺口

| 类别 | 名称 | 判定标准 | 可机械检测 |
|---|---|---|---|
| **K1** | 空白格 | 表格或正文出现空单元格、占位符（`TBD`/`待定`/`待补`/`—`/`N/A`/`未公开`） | ✅ |
| **K2** | 悬空边界句 | 出现边界词（`未披露`/`未公开`/`未说明`）但同一逻辑块内**没有**结论、替代口径或影响评估 | ✅ |
| **K3** | 维度缺口 | 报告类型对应的**标准维度清单**有未覆盖项 | ✅ |
| **K4** | 来源缺口 | 含数字的表格或整章没有来源标注 | ✅ |
| **K5** | 未裁决冲突 | 两处结论互相矛盾且未给裁决口径与适用条件 | 人工裁定 |

### 4.2 三条闭合路径

- **C1 查证补齐**：检索到事实 → 事实 + 来源。
- **C2 替代口径定论**：原始数据不可得，但可用可核查的替代证据推出结论 → **推断值 + 置信度 + 推导链**，
  且必须**分区隔离**（正文主体只用已证实事实，推断值集中在独立章节/表格并标注类型）。
- **C3 边界定论**：确认无任何可得证据 → **查证路径 + 影响评估 + 本报告判断**三要素齐全。

**C2 与 C3 都必须给出结论。**「查不到」是**过程**，不是**交付物**。

### 4.3 绝对硬门禁（无豁免）

- 交付前必须跑零缺口门禁脚本，**结果全绿**才可交付；
- **不存在「经批准即可留缺口」的情况**——确有不可闭合项时，正确动作是**继续查**或**把结论写死**；
- 门禁红时**禁止**通过改写门禁脚本、放宽关键词、删检查项的方式让它变绿；
- 门禁脚本：`skills/professional-report-deliverable/scripts/zero_gap_gate.py`（扫描 `.md`/`.html`/`.pdf` 三层）；
- 完整规范（含标准维度清单、置信度判别表、交付自检清单）见 **`ZERO-GAP-STANDARD.md`**。

## 5. R10 脱敏（商业机密零出现）

### 5.1 规则本体

用户提供的原始材料里带着**品牌名、产品名、型号、内部代号**。它们一旦随交付物流出去，
就是把商业机密连同报告一起递了出去。因此：

> **所有对外交付物中，不得出现用户材料里的任何商业机密标识。
> 唯一允许出现的用户标识是 R1 署名。**

适用范围 = 本协议 §适用范围里的全部交付物，**不分内外部分析**。

### 5.2 三层都要查（机械门禁，不靠肉眼）

| 层 | 查什么 | 工具 |
|---|---|---|
| `path` | 目录名 + 文件名 | `bin/qa_leak.py` |
| `text` | md / txt / csv / tsv / json / html / xml / yaml / py / js 等可检索文本 | 同上 |
| `pdf_text` | PDF 每页文本层 | 同上 |

**图像像素层门禁扫不了**（不做 OCR）。因此规则是**制图阶段就避开**：
生成式底图按零文字出，图表标题与图例从事实源取且不带品牌。

### 5.3 脱敏怎么做

| 做法 | 判定 | 理由 |
|---|---|---|
| **整值移除** | ✅ 正确 | 文字里直接不写那个值，只保留论证本身（「三处载体载有同一序列号，逐字一致」） |
| **假代号**（S-7K3M9Q 之类） | ❌ 错误 | 假代号仍能指回原件，等于没脱敏；「你这种方式，还不如不脱敏」 |
| **生硬灰框** | ❌ 错误 | 视觉上像 bug |
| **档案式遮蔽贴片** | ✅ 正确 | 照片用深墨底 + 细亮边 + 一排圆点表示「此处原有数值」；二维码实心遮盖（只做马赛克仍可解码） |
| **加整节脱敏说明** | ❌ 错误 | 只在封面横幅、页脚、边界表各加一行 |

### 5.4 保留什么

**公开目录信息**（参考号 / GTIN / 机芯号）**不脱敏**——遮蔽它没有安全收益，
反而让报告失去对象指向。保留时须在报告里写明保留理由。

### 5.5 内部版与交付版物理分开

- 未脱敏的内部版**不得留在交付目录里**。
- 交付目录里只有脱敏件，且**不得混着未脱敏副本**。
- 报告正文里不出现任何品牌标识，**只出现 R1 署名**。

### 5.6 门禁怎么跑

```powershell
# 交付前必跑；退出码 1 = 有命中 = 不许交付
python %AGENTOS_HOME%\bin\qa_leak.py <交付目录> --json <leak_report.json>
```

> 退出码 **2 = 词表读不到 / 路径不存在**。**退出码 2 绝不能当成 0**：
> 读不到词表等于**没检过**，不是检过了没发现。

词表：`policies/REDACTION-TERMS.json`（只增不删；新增标识须写明来源材料）。
MCP 侧同名工具：`metal-dfm-kernel` 的 `scan_redaction`，与本脚本共用同一份实现。
