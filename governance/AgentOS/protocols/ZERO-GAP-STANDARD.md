# AgentOS 零缺口交付协议 v1.0

> 用户 2026-10-23 裁决：**「以后所有的报告不能有缺口」**。
> 本协议把这句话变成**可机械执行、可阻断交付**的门禁。非建议、非可选。
> 与 `DELIVERABLE-STANDARD.md` 并列执行，优先级相同。

---

## 0. 一句话定义

**零缺口 ≠ 零不确定。**

零缺口 = 报告里**每一处**都落到一个**明确结论**；不允许留下「未公开 / 待确认 / 留空 / —」这类
悬空项，让读者自己填空。

| | 允许 | 禁止 |
|---|---|---|
| 事实 | 「A 值为 470.42 亿元（招股书）」 | 「A 值约 470 亿元左右（未核）」 |
| 边界 | 「经三条路径查证后确认不可得；影响为 X；因此本报告判断为 Y」 | 「A 未披露，无法评估」 |
| 推断 | 「推断 A ≈ X（置信度中，推导链见 §3）」 | 把推断值混进正文当事实陈述 |

**判别口**：把报告给一个完全没读过原始资料的人看，他能不能对**每一处**给出自己的判断？
不能的地方，就是缺口。

## 1. 五类缺口（K1–K5）

| 类别 | 名称 | 判定标准 | 可机械检测 |
|---|---|---|---|
| **K1** | **空白格** | 表格或正文出现空单元格、占位符：`TBD`、`待定`、`待补`、`待核实`、`XX`、`—`、`N/A`、`未公开`、`暂无`、`未知` | ✅ |
| **K2** | **悬空边界句** | 出现边界词（`未披露`/`未公开`/`未说明`/`不详`/`未完整公开`/`未全量披露`/`未拆分`），但**同一句或同一表格行内没有给出结论、替代口径或影响评估** | ✅ |
| **K3** | **维度缺口** | 报告类型对应的**标准维度清单**存在未覆盖项（清单见 §6） | ✅ 清单比对 |
| **K4** | **来源缺口** | 数字或结论无来源，或来源无法定位到具体文件/章节/网址/日期 | ✅ |
| **K5** | **未裁决冲突** | 两处结论互相矛盾，且未给出裁决口径与适用条件 | ✅（脚本找候选，人工裁） |

### 1.1 什么是**不算**缺口

以下写法是**合法的结论**，K1/K2 不得误报：

- 「X 不存在 / 不存在此类风险」——有查证依据的否定结论。
- 「X 不在本报告范围内」——明确划界且不影响任何结论。
- 「X 不适用于本标的」——有理由的排除。
- 「招股书原文：……」——直接引用原始披露。

### 1.2 一句话能塞进结论的，**不许**写成缺口

把「未披露单位成本下降幅度」写成 K2 缺口是**懒惰**，因为同段就能补：
「公司披露『单位成本继续下降』但未给数值；本报告以 2025 年单位成本 X 元/GB 与 2026Q1
均价 Y 元/GB 反推，单位成本降幅落在 Z%–W%（置信度中，推导链见第 X 章）」。

## 2. 三条闭合路径（每个缺口必须落其一）

| 路径 | 含义 | 交付物形态 |
|---|---|---|
| **C1 查证补齐** | 检索到事实 | 事实 + 来源（文件、章节、日期、网址） |
| **C2 替代口径定论** | 原始数据不可得，但可用**可核查的替代证据**推出结论 | **推断值 + 置信度 + 推导链**（呈现规范见 §3） |
| **C3 边界定论** | 确认任何公开渠道均无证据 | **查证路径 + 影响评估 + 本报告判断**（三要素见 §4） |

**铁律：C2 与 C3 都必须给出结论。**
「查不到」是**过程**，不是**交付物**。交付物必须是过程之后的那个判断。

## 3. C2 推断值的呈现规范（分区隔离 + 置信度 + 推导链）

用户 2026-10-23 明确裁决：允许推断，但**必须分区隔离 + 标注置信度 + 给出推导链**。

### 3.1 分区隔离

- **正文主体**只使用**已证实事实**（C1）。正文结论句不得以推断值作为前提。
- 推断值集中在**独立章节或独立表格**，标题或表头必须含「**推断**」「**估算**」「**测算**」字样。
- 章节开头一句范围声明：「本章数值均为基于公开信息的推断，非公司披露值。」

### 3.2 置信度标注

每条推断必须标 `高` / `中` / `低`，并给判据：

| 置信度 | 判据 |
|---|---|
| 高 | 推导链上的每个输入都是公司披露值或法定公开值，仅组合方式为推断 |
| 中 | 推导链含 1–2 个外部估算输入（行业基准、可比公司、公开统计） |
| 低 | 推导链依赖多项外部估算，或存在方向性争议 |

### 3.3 推导链

每条推断必须能回答：**前提是什么 → 用了什么方法 → 得到什么 → 什么情况下会失效**。
推导链要写进表格的「依据/推导」列，不是脚注。

### 3.4 推断的使用限制

- 推断值**不得**用于支撑「必须精确值才成立」的结论（如精确的份额排名、精确的估值倍数）。
- 推断值**不得**在摘要/核心判断中与事实值混排而不加区分。
- 中英两版**必须同步分区**，推断标签在英文版不得丢失（`Estimated` / `Derived` / `Inferred`）。

### 3.5 表格形态（强制）

| 结论 | 类型 | 置信度 | 依据 / 推导 | 对结论的影响 |
|---|---|---|---|---|
| … | 推断 | 中 | 前提 → 方法 → 结果 → 失效条件 | … |

## 4. C3 边界定论的三要素

不可得的事实，用**三要素**写成结论，缺一不可：

1. **查证路径**——列清查过哪几条渠道（招股书 / 问询回复 / 年报 / 交易所动态 / 招聘平台 / 司法文书 / 公司官号）。
2. **影响评估**——缺这一项对最终结论的影响方向与量级（影响大 / 影响小 / 仅影响精度不影响方向）。
3. **本报告判断**——结论仍然要落地，且不弱于原文。

**反面教材**（不合格）：「员工流失率未公开，无法评估留才能力。」
**合格写法**：「经招股书员工章节、2026 届校招简章、企查查与两家招聘平台的员工点评共四条路径查证，
未见公司披露流失率；该缺口对『留才能力』结论的影响是**方向可判、量级不可判**——公司三年员工
总数由 A 增至 B、研发人员由 C 增至 D，净增为正且研发增速高于总人数增速，**据此本报告判断留才
能力不构成实质风险，但无法给出年度流失率**。」

## 5. 绝对硬门禁（无豁免）

用户 2026-10-23 明确裁决：**任何一项缺口未闭合就不许交付**。

| 规则 | 内容 |
|---|---|
| G5-1 | 交付前必须跑零缺口门禁脚本，**结果全绿**才可交付 |
| G5-2 | **无豁免通道**：不存在「经批准即可留缺口」的情况；确有不可闭合项时，正确动作是**继续查**或**把结论写死**，不是申请豁免 |
| G5-3 | 门禁红时，**禁止**通过改写门禁脚本、放宽关键词、删检查项的方式让它变绿 |
| G5-4 | 门禁报告必须随交付物一起留存（`qa_report`），供复核 |
| G5-5 | 已交付报告若事后发现 K1–K5 缺口，视为**交付缺陷**，须发勘误并重跑门禁 |

### 5.1 门禁实现

- 通用脚本：`skills/professional-report-deliverable/scripts/zero_gap_gate.py`
  扫描 `.md` / `.html` / `.pdf` 文本层三层，输出 PASS/FAIL 与**可审阅清单**（不是二值判定）。
- 报告项目可另写本项目专用维度清单（K3），但**不得关闭** K1/K2/K4 三类通用检查。
- 判定必须能**逐条复现**：每条 FAIL 要给出文件名、行号/页码、命中片段、缺什么。

### 5.2 交付自检清单（人工过一遍，脚本查不出的部分）

- [ ] 摘要/核心判断里有没有把推断当事实陈述
- [ ] 每一张表：有没有整行都是"待补"
- [ ] 每个"未披露"旁边有没有跟着结论
- [ ] 维度清单有没有漏项
- [ ] 中英两版的缺口处理是否对称（英文版不能悄悄删掉中文版的缺口项）

## 7. 与既有协议的关系

- 本协议是 `DELIVERABLE-STANDARD.md` 的 **R5**，与 R1–R4 并列，**同为最高级**。
- 本协议是 `TRUTH-AND-EVIDENCE.md` 中 `unknown` 真值级的**处置规范**：
  `unknown` 是**真值标签**，不是**交付状态**——标了 unknown 之后必须给出结论。
- 与 `QUALITY-GATE.md` 并列执行，不互相替代：质量门禁管"做得对不对"，
  零缺口门禁管"有没有留白"。
- 门禁脚本与本协议由 `skills/professional-report-deliverable` 引用，所有报告类 Skill 须指向本协议。
