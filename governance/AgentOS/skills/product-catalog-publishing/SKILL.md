# 产品目录发布（Product Catalog Publishing）

> 治理唯一源：`${AGENTOS_HOME}`。本文件只提供操作方法，不复制治理正文。

---

## 0. 一句话

**目录数据只有一个源；列表页、详情页、下载文件三者由同一份数据生成；每个链接在发布前必须实测可达。**

---

## 1. 为什么需要它

产品站点最常见的四类事故，本方法逐条挡住：

| 事故 | 表现 | 本方法如何挡 |
|---|---|---|
| **链接指向错误内容** | 37 张卡片全指向 2 个不相干详情页 | 详情页由数据生成，slug 与数据绑定，禁止手写重复页 |
| **下载是空按钮** | `<button>下载</button>` 无 href，点击无反应 | 下载目标必须是**真实存在的文件**，生成后实测 HTTP 状态与字节数 |
| **数据源分裂** | 后台库 6 条 vs 页面 37 条，接口返回 0 条 | 开工前先做**数据源对账**，裁决并记录，不用"接口有数据"当唯一依据 |
| **目录页漂移** | 手改 N 页，N+1 页忘记同步 | 页面由生成脚本产出，改数据 → 全量重生成 |

---

## 2. 第零步：数据源对账（不可跳过）

**在写任何页面前**，把"页面上展示的产品"与"接口返回的产品"逐条列出对比：

| 检查 | 取证方式 | 判据 |
|---|---|---|
| 页面卡片数 vs 接口条数 | 抓页面卡片 + 读接口 JSON | 数量与条目一致，或明确裁决以哪边为准 |
| 分类值是否同一套体系 | 比对接口 `category` 值与页面目录 | 分类名能对上；否则接口分类查询会返回 0 条 |
| 详情链接是否指向对应条目 | 逐条比对链接目标与卡片标题 | 链接目标内容 == 该卡片 |
| 下载目标是否真实存在 | 对每个下载 URL 发 HTTP 请求 | 200 + 非零字节 |

> **对账结论必须落盘并带证据等级**。裁决"以哪边为准"是产品决策，不是技术细节。

### 2.1 数据源裁决的判据优先级

1. **线上实际展示的内容**（当前公网可见的）—— 用户正在看到的
2. **内容更完整的一方**（37 条 vs 6 条，6 条若是样例则更少者不是真相）
3. **可维护性**（有 API 但分类体系对不上的，不可用）

裁决结果与理由写进决策记录，冲突**不静默抹平**。

---

## 3. 目录数据模型

单一数据源（项目自有文件），字段最小集：

```json
{
  "slug": "st-100",
  "model": "ST-100",
  "title": "台式力学试验机",
  "category": "test-machines",
  "category_label": "测试机台",
  "type": "desktop",
  "specs": "5N～50kN · 精度0.02%FS",
  "tags": ["GB/T 1043", "ISO 527"]
}
```

**规则** `[规范]`：
- `slug` 全局唯一 —— 重名型号加分类前缀消歧（`tm-sen-200` / `acc-sen-200`）
- `slug` 是详情页 URL 与 PDF 文件名的唯一依据，**不可手工另取**
- `title` / `model` / `specs` / `tags` 需要有真实来源（现有站点文案或业主提供）

> ⚠️ 若产品参数来自站点旧文案，那只是**转录既有内容**，不是新增断言。
> 参数真实性由业主/产品线确认，交付时必须显式声明这一点。

---

## 4. 三方一致的生成拓扑

```
products.json （唯一数据源）
    │
    ├──→ /products/index.html            列表页：每条 2 个链接
    │         ├── 产品介绍 → /products/<slug>/
    │         └── 资料下载 → /downloads/<slug>.pdf
    │
    ├──→ /products/<slug>/index.html     详情页（37 个，由脚本生成）
    │         └── 资料下载 → /downloads/<slug>.pdf
    │
    └──→ /downloads/<slug>.pdf           规格书（真实 PDF，非占位）
```

**为什么用生成脚本而不是手写**：
手写 N 个详情页 = N 份重复 = 漂移风险高（实测：现有 37 张卡片指向 2 个错内容页面）。
生成脚本让"改一条数据 → 列表页 + 全部详情页 + PDF 同步"成为默认路径。

**禁止**：把产品数组硬编码进 HTML。数据只在 `products.json` 里。

## 5. 资料下载（PDF 规格书）

### 5.1 硬规则

| 规则 | 说明 |
|---|---|
| **必须是真实文件** | 链接目标存在、HTTP 200、字节数 > 0 |
| **禁止空按钮** | `<button>下载</button>` 不算下载入口 |
| **禁止占位 PDF** | 空壳 PDF 欺骗下载者，判为未完成 |
| **内容与数据一致** | PDF 里的型号/参数必须来自同一份 `products.json` |
| **可离线打开** | 不依赖外网资源（字体内嵌或使用标准 CJK CID 字体） |

### 5.2 CJK PDF 生成

reportlab + Adobe 标准中文 CID 字体（无需外部字体文件）：

```python
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.cidfonts import UnicodeCIDFont
from reportlab.pdfgen import canvas

pdfmetrics.registerFont(UnicodeCIDFont("STSong-Light"))
c = canvas.Canvas(out_path)
c.setFont("STSong-Light", 16)
c.drawString(60, 780, "苏州海酷电子科技有限公司 — 产品规格书")
```

**发布前必须验证**：生成后用 PDF 解析器或 `pdftotext` 抽出文本，
确认中文与数字都正确（字体选错会得到空白或乱码，而文件大小仍然正常 ——
大小正常不代表内容正确）。

### 5.3 规格书最少内容

产品名称 / 型号 / 分类 / 技术参数 / 适用标准 / 联系方式 / 文档版本与日期。

## 6. 链接可达性核验（发布前门禁）

发布前对**每一个**出站链接跑一遍：

| 检查 | 判据 |
|---|---|
| 内部链接可达 | HTTP 200，且不是被 301 到别处的死链 |
| 详情页 ↔ 列表页一致 | 详情页的型号/标题与列表中该条一致 |
| 下载可达且非空 | HTTP 200 + `Content-Length > 0` + 可解析出文本 |
| 无 404 死链 | 页面上所有 `href` 全部实探，包括 nav / footer |
| 无占位 href | 无 `href="#"`、`href="javascript:void(0)"` 冒充功能 |

**只探首页不算数**。导航与页脚里的死链是最高频的遗漏点。

---

## 7. 可访问性（最低线）

- 语义标签：`nav` / `main` / `footer` / `article` / `h1-h3` 层级不跳级
- 链接有可读名称；下载链接文本含"下载 + 型号"，不只写"下载"
- 对比度 ≥ 4.5:1（正文）
- 键盘可达：所有链接/按钮可 `Tab` 到达，`:focus-visible` 有可见轮廓
- 图标按钮有 `aria-label` 或 `title`
- `lang` 属性正确；`alt` 不为空占位

> 视觉与对比度的**实际渲染效果**需截图复核，静态检查不构成视觉结论。

---

## 8. 发布与回滚

1. **备份**：改前把目标目录整目录复制到 `<site>/.backups/<timestamp>/`
2. **生成**：在临时目录生成全部产物，**先本地/内网自测**
3. **发布**：写入线上目录（写即生效的站点需分批）
4. **留证**：发布后立刻实探每一个链接，保存 HTTP 状态表
5. **回滚**：备份目录原样恢复；git 仓库作为二次回滚

**写即生效的站点**（`Restart=always` 的 systemd 服务监听同一目录）：
没有灰度，错误内容即时公开 → 分批发布 + 每批留证。

---

## 9. 常见失败及处理

| 失败 | 处理 |
|---|---|
| 列表有 N 条，详情只有 2 个 | 详情页必须由数据生成，不手写 |
| 下载按钮无 href | 生成真实 PDF，链接到文件 |
| 接口分类查询返回 0 条 | 分类值与页面分类体系不对齐，先做数据源对账 |
| 生成脚本覆盖了手工修补 | 手改必须改数据源，不改产物 |
| 改了数据忘了重生成 PDF | PDF 与 HTML 共用同一次生成，不分两次跑 |
| 只验证了首页 | 全量链接实探，含 nav/footer |
| PDF 大小正常但内容是空的 | 用文本抽取验证，不看文件大小 |

---

## 10. 边界

- 本方法不认证产品参数真实性，也不替代业主对规格的确认。
- 静态检查不构成视觉或对比度结论；需截图复核。
- 目录结构的最终裁决权在业主/产品线，不在本方法。
