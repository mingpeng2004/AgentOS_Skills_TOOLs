# DFM / 设计规范配图语法

> 一条设计规范 = **一张图 + 要点清单 + 机理理由 + 失败模式**。少任何一项都算未完成。
> 工具：`scripts/dfm_panel.py`（装配 + 门禁）、`scripts/iso_render.py`（等轴测实体）。
> 样板：`assets/samples/dfm-panel-sample-zh.png` / `-en.png`，契约样例：`assets/templates/dfm-spec-sheet.json`。

## 1. 只有一种图不合格：骨架图

线框式示意图 = AI 味。但**判不合格的依据不是"有没有受光三面"，而是"是不是骨架图"**。

> **骨架图** = 用轮廓线勾了个零件、标了文字标签，
> 而它所讲的关系**本可以**由实景底图或带填充的实体表达。

**判别口**：这张图里有没有**零件**？
有零件却没有填充 ⇒ 骨架图（不合格）；
根本没有零件，画的是参考线或曲线 ⇒ 符号关系图（合格）。

B2 路线（带填充的实体 / 剖面）要具备的要素：

| 要素 | 作用 | 实现 |
|---|---|---|
| **带填充的实体面** | 让体积与材质读得出来 | `Iso.prism` 按面朝向算明暗，顶面叠无硬边渐变 |
| 剖面线 / 切面纹理 | 让材料读得出来 | `Iso.speckle` 玻纤颗粒，裁切在面轮廓内 |
| 接地投影阴影 | 让物体"落地"，不悬空 | `Iso.shadow` |
| 制图式尺寸线与引出 | 让关系读得出来 | `Iso.dim_v/dim_h/callout` |

**先试过"内缩一块浅色多边形"做高光——读起来像挖了个凹槽**（眼睛看到的是边框和底）。
没有硬边的真渐变才让实体读起来是实的。

> **不要拿"受光三面"当唯一标准**：金属制程库 118 个带填充的工程剖面
> （剖面线 + 引出线 + 尺寸线）都是合格的，套"必须受光三面"会把它们全判不合格。

## 2. 三条底图路线，选哪条

| 路线 | 底图 | 适用 | 工具 |
|---|---|---|---|
| **A. 实景概念渲染** | 生成式手绘淡彩实景（**零文字零人脸**） | "这个零件/装置做出来长什么样" | 本 skill 的两层法主流程（生成 → `text_screen.py` → `overlay_compose.py`） |
| **B. 带填充的工程剖面 / 等轴测实体** | 程序化实体（matplotlib） | "这条规范的几何关系是什么"（壁厚/筋厚/圆角/流向/水路） | `iso_render.py` 画实体 → 导 PNG → `dfm_panel.py` 装配 |
| **C. 符号关系图** | 程序化参考线 / 曲线 / 力矢量 | "两个参考量之间的关系"（熔点 vs 服役温度、时效曲线、受力方向） | 程序化绘制（**画面里没有零件**） |

**判别口**：要表达"外观与实景"走 A，要表达"几何与尺寸关系"走 B，
要表达"参考量之间的关系"走 C。
三者都遵守**底图不写字、文字全部程序画**——B、C 天然满足（程序画的），A 必须过筛查闸门。

> 实测：同一套两层法在三个项目都跑通了 —— 湘乡 50 届 43 张生成式底图 + 80 张成品图；
> 塑胶材料库 DFM 章节 12 张生成式底图 + 12 组等轴测实体面板；
> 金属制程库 DFM 章节 240 cell 全量审计（A 形态 120、B 形态 118、C 形态 2）。

## 3. 面板版面（同一套分栏，不能各画各的）

```
┌──────────────────────────────────────────────────────────┐
│ ① 规范标题                                                │  ← 编号 + 中英标题
├───────────────────────────────┬──────────────────────────┤
│  引出标签 ····                │  · 要点 1                │
│  引出标签 ····                │  · 要点 2                │
│                               │  · 要点 3                │
│      【实体区】               │                          │
│      等轴测实体 / 实景底图    │  机理理由（砂铜色）      │
│      引出线指向具体特征       │  讲"为什么会这样"        │
│                               │                          │
│                               │  失败模式（砖红）        │
│                               │  讲"做错会怎样"          │
├───────────────────────────────┴──────────────────────────┤
│ 设计规范 · 工程判断（非厂商数据）                          │  ← 声明，区分工程判断与厂商数据
└──────────────────────────────────────────────────────────┘
```

固定分栏（`dfm_panel.py` 里的 `REGION_BODY` / `REGION_TEXT`）：
实体区 x ∈ [0.04, 0.60]，文字列 x ∈ [0.64, 0.98]。**实体不得侵入文字列**。
`iso_render.py` 的 `check_layout()` 会把这条当硬门禁（并有"放大后越界被拦下"的负控制）。

## 4. 四段文案各写什么

| 段落 | 写什么 | 不写什么 |
|---|---|---|
| 要点清单 | 2~4 条**可判定的数值或结构约束**（"筋厚 ≤ 0.6 × 壁厚"） | 不写"要更结实"这种无法判读的话 |
| 机理理由 | 为什么会这样：收缩速率差、冷却先后、纤维取向、应力集中 | 不重复要点，不写营销话 |
| 失败模式 | 做错会怎样：缩痕 / 翘曲 / 纤维堆积 / 缺口敏感 | 不写"质量下降" |
| 声明 | 工程判断 vs 厂商数据 | 厂商没述的不引用任何数值 |

**理由段是 DFM 配图的价值所在**：只有图没有理由，读者不知道该怎么用这条规范。
理由要讲**机理**（为什么会这样），不是复述规则。

## 5. 引出标注的坐标语义

契约里的 `fx/fy` 是**原图内相对坐标（0..1，原点在左上角）**，渲染时映射回
"裁切 + 摆放"后的位置 —— 所以换一张底图不用重新标点。

- **锚点要实测，不要照抄模型写的**：画底图时把特征点的屏幕坐标返回出来，
  换算成原图相对坐标写进契约。模型写的锚点必然是名义中心。
- **锚点必须落在有墨迹的地方**：门禁会核对锚点像素与背景的差值 ——
  指一条到空纸上的引出线等于没有引出线。
- 标签落在实体区顶部的留白里，并**避开徽章**（装配器按实测字宽钳位，不许压住 √/×）。
- 引出线不得飞出画布，也不得穿过实体；
- `fx/fy` 越界（不在 0~1）会被门禁拦下。

> 踩过的坑：缩放基准早先误用 `dw / orig_w`，而显示宽 `dw` 是**裁切后**的图宽 ——
> 裁掉多少，锚点就偏多少。正确基准是 `dw / trimmed_w`。

## 6. 门禁（`dfm_panel.py --gate`）

| 检查 | 判据 |
|---|---|
| 覆盖率 | `meta.count` 必须等于实际规范条数 |
| 完整性 | 每条规范必须有中英标题、**≥2 条要点**、中英理由、中英失败模式、底图 |
| 双语纯度 | 英文侧不得含任何中文字符 —— **含页脚声明行** |
| 数值自洽 | 面板里出现的**每个数字都必须能在事实源里找到出处** |
| 失败模式可溯 | 失败模式段必须是事实源的**逐字子串** |
| 锚点合法性 | `fx/fy` 必须在 0~1，**且锚点像素有墨迹** |
| 判定完整 | 每个底图都要**显式声明** good / bad / neutral；未声明判不合格 |
| 版面守卫 | 实体不得越界或侵入文字列；右列文本不得溢出面板 |

> 数值自洽这一条是"数据合理正确才是根本"的机械化守门：
> 事实源里没有的数字（编的、抄错的、记串版本的）一律拦下。
> **失败模式可溯**是同一条纪律在文案上的延伸：§9.13 要求渲染值与事实源逐字一致，
> 失败模式最容易变成"自己写的一句话"，所以它必须是逐字子串。
>
> 负控制用例（每条坏情形都必须被抓住，共 13 条）：
> 缺机理理由 / 英文混中文 / 无出处数字 / 缺底图 / 条数不符 / 未声明判定 /
> 缺失败模式 / 自撰失败模式 / 锚点落在空白处 / 英文页脚含中文。

## 7. 工作流

```bash
# 1) 写规范契约（结构见 assets/templates/dfm-spec-sheet.json）
# 2) 画实体（路线 B）
python scripts/iso_render.py --demo wall_iso.png      # 参考面板，可照着改几何
# 3) 过门禁 + 出面板
python scripts/dfm_panel.py --spec dfm_spec.json --facts facts.md --outdir figures
# 4) 路线 A 的底图要先过文字筛查
python scripts/text_screen.py --dir raw --out _text_hits.json --crops _texthits
```

## 8. 常见坑

- **骨架图当成图交了** → 用 `iso_render.py` 画**带填充的实体**，别手画线框。
  但图里根本没有零件、画的是参考线或曲线的（符号关系图）是**合格**的。
- **理由段写成要点的复述** → 理由必须讲机理。
- **失败模式只写在要点里** → 必须在理由段里被点明，否则读者读完理由仍不知道做错会怎样。
- **失败模式自己编一句** → 门禁要求它是事实源的逐字子串；要改写就先改事实源。
- **数值随手写** → 走门禁，事实源里没有的数字会被拦下。
- **英文版混中文** → 门禁会拦；**页脚声明行也算**，它曾被硬编码成中文。
- **实体压到文字列** → `check_layout()` 拦；别靠眼睛看缩略图。
- **引出标注飞出画布 / 指到空纸上** → 锚点实测、门禁核对墨迹；标签按实测字宽钳位。
- **三面板参数序列强排成好左坏右** → 好的在中间是语义正确的（§9.9.4 只管两面板对照）。
- **把 DFM 配图当数据图表用** → 要表达精确数值关系的图仍走数据图表（§3），生成图/工程插画不替代图表。
